未使用付费模型 API，未把扶摇密钥或行情发送给大模型。

## AI 参与的环节

1. **工程实现**：页面、API、校验、证据展示、比较、限流与部署防护。
2. **意图实验**：模型只允许输出 `outcome / conditions / issues`。单位、报告期、窗口来自指标注册表；证据必须是原文连续子串。
3. **把关**：`validateIntent` v2 拒绝改写证据、错误方向、不支持指标、OR、报告期/窗口未写明等情况。门控只拒绝，不补全或改阈值。
4. **候选人修正**：提示词从 v1 到 v4，只为修复「证据必须逐字复制」；没有为提高通过率放宽校验。公网最终不依赖该模型，改为程序化澄清，避免把 NO-GO 模型部署到评审 URL。

## 验证结论（可追溯）

Phase 3A，2026-10-15，两轮共 60 次真实模型调用：

| 指标 | v1 | v2 |
|---|---:|---:|
| 完整正确 | 6/30 | 16/30（53.3%） |
| 明确请求可用 | 5/12 | 7/12（58.3%） |
| 关键错误逃逸 | 5 | 0（仅本批样本） |
| 结论 | NO-GO | **NO-GO** |

被拦住的错误包括：把「不要 PE 大于 20」做成排除等于 20、把股息率 3% 映射成年报 ROE、把 OR 当 AND、把提示词示例里的 17.3 写进注入用例。

Phase 3B，2026-10-16：v4 修复了「市盈率不超过 20 倍」的原文复制问题，完整指定回归 **10/16**。失败项（否定边界、OR、股息率）仍被接口拒绝，不能宣传成「已经理解」。

2026-10-16 浏览器 UAT（本机生产构建，端口 3010）：

- 输入「PE不超过20倍」→ 确认 → 真实筛选：快照 `957d9df5-47af-43cc-97c5-1fbfda48f50e`。平安银行 PE 5.161932 入选；贵州茅台 20.217234、同花顺 41.4026 排除。上述值与扶摇 `data.item[].pe_ttm` 一致。
- 阈值改为 45 后同快照比较：上游计数 7→7，新增 0 次。茅台、同花顺新增入选，平安银行仍入选。

## 候选人明确否决的结果

- 不把校验拒绝当成模型理解正确。
- 不把本机 3B 模型接到公开 URL。
- 不把单年 ROE 解释成「经营改善」。
- 不把比较或刷新后的价格变化说成回测收益。
- 不在公开仓库或前端暴露 API Key。
