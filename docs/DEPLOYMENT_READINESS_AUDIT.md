## 零新增支出约束与免费方案核查

Koyeb 依据：[注册与收费 FAQ](https://www.koyeb.com/docs/faqs/pricing)、[免费实例约束](https://www.koyeb.com/docs/reference/instances)。不采用到期后自动收费的试用方案。

Render 的 15 分钟空闲休眠与当前 15 分钟快照 TTL 接近，但不能据此保证会话：主动重启或发布仍可提前丢失。演示应先正常打开页面等待唤醒，再筛选并及时比较；不依靠人工保活脚本承诺全天在线。平台冷启动页发生在应用运行之前，应用本身无法消除它。休眠、低内存、云端扶摇连接或目标地区访问不达标时，再评估备选，而非升级付费。

## 托管选择与快照可靠性

应用有三个 Node.js API 路由，`/api/screen` 与 `/api/compare` 为动态服务端请求。首页能预渲染不代表整个产品可以静态部署；应使用 Node Web 服务或兼容的函数环境。[Next.js 部署说明](https://nextjs.org/docs/app/getting-started/deploying)。

| 方案 | 现有快照能否可靠连接两次请求 | 最小代价 / 判断 |
|---|---|---|
| Render Free 单实例 Node Web 服务 | 同一进程、未重启、未过期/淘汰时可以；唤醒后内存无法保留 | 零支出首选；保留 Map，无需数据库。保持单进程，接受冷启动和显式刷新；演示期间避免发布。 |
| Vercel + 现有 Map | 不保证 | 不可原样使用；函数会自动扩展为多个实例，同一 Cookie、同一区域、`globalThis` 或延长函数运行时间都不保证进程归属。[并发与实例扩展](https://vercel.com/docs/functions/concurrency-scaling)。 |
| Vercel Hobby + Upstash Redis Free | 有实现与验收后可以 | 零支出备选；增加一个免费服务及异步存储适配，受免费额度与用途限制；本次没有实施或验证。 |

当前 `lib/server/sessions.ts` 将快照、原始规则、owner 与 expiresAt 保存于进程 Map。绝对有效期 15 分钟，全局 100 份、每会话 3 份、每份快照最大 128 KiB；达到上限会提前淘汰，因此并不承诺完整存活 15 分钟。`globalThis` 只防止同进程重复创建，并非跨进程数据库。

`/api/compare` 在服务端读取该快照并执行原有纯函数，没有任何扶摇调用，这是正确边界，应保留。缺失/归属不符返回 404、到期返回 410，已有中文刷新提示；重启后失效不能伪装成同快照成功，也不能静默重新取数。

若采用共享存储，最小改动只涉及会话存储与 handler 的异步读取：保存原快照及原始规则、owner 绑定、绝对 TTL、容量/体积上限与淘汰政策；读取后恢复只读约束，继续使用现有验证器和确定性引擎。跨实例的限流、并发锁也必须共享，锁有过期保护，存储故障明确失败。无需账号、策略库、消息队列或金融数据写回浏览器。不建议临时文件、SQLite 或“尽量路由到原实例”作为 Serverless 修补。

## 必须修复或完成的上线阻塞

1. **先确定与状态模型兼容且零支出的目标。** 首选 Render Free 单实例 Node，明确休眠与重启限制；若改用函数运行或要求重启后保留快照，须另行批准免费共享 TTL 存储。不能只发布首页后宣称 What-if 已上线。
2. **修复 HTTPS 代理下的来源校验与 Cookie。** `lib/server/handlers.ts` 以内部 URL 协议拼接 Host，已在受控测试中复现 403；Secure 也依赖内部协议。建议配置明确的公开 `APP_ORIGIN`（完整 HTTPS origin）并按该值检查浏览器 Origin、设置 Secure，开发模式另有明确本地配置。不要无条件信任任意客户端转发头。无 Origin 的请求不是身份认证，频率限制仍必须有效。
3. **补充公开取数接口的实际限流与预算。** 当前同 owner 仅阻止重复并发，全进程最多 8 个活跃取数会话；清除 Cookie 或连续请求可反复使用服务端密钥。每次筛选需 7 次上游请求，每快照同时最多 2 次，全进程最多可能 16 次。需要可信代理 IP 的频率限制、会话冷却、全局取数预算与较低全局并发上限；429 提供中文说明和 Retry-After，配额耗尽不取数。计数器自身必须有 TTL 与容量上限。不能把 CORS/Origin 检查当作防滥用机制。限额应按实际账号额度配置，当前没有已核实的供应商 QPS/每日额度，不能声称现有并发满足供应商限制。
4. **锁定运行时并配置服务端环境。** `engines.node >=24` 无上界，建议改为 `24.x`；保留锁文件与现有 TLS 校验。云端只在秘密环境变量配置 `FUYAO_API_KEY`，不上传 `.env.local`，不使用 NEXT_PUBLIC 前缀，不把密钥传给构建日志/命令参数/浏览器。启动使用生产模式，监听平台 PORT 与 0.0.0.0；安装构建阶段必须有 TypeScript 等开发依赖。[Render Node 版本选择](https://render.com/docs/node-version)、[Vercel 支持版本](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)。
5. **在选定云环境验证上游与请求时间预算。** 本机系统 CA 可用不证明云端证书、DNS、出站区域、IP 限制或账号授权可用。需要目标运行时实际调用现有三个端点、核对三股的真实值/证据、错误与延迟，并由目标访问地区浏览器完成流程；不能关闭 TLS 校验。公开显示供应商数据的权限及额度仍需核对，PRD 已明确要求，当前未确认。

时间预算说明：客户端每个上游请求有 15 秒超时，固定 HTTPS、禁止跳转、不自动重试；估值一次后逐股执行三组双并发请求，异常情况下理论等待约 `15 + 3×15 = 60 秒`，另有处理开销。当前没有整次筛选 deadline，也不把浏览器取消向上游传播。最小实现应明确整次请求预算（例如先以 30 秒为可配置目标，需实测校准），终止剩余请求并保留已有成功指标，未完成指标仍为 UNKNOWN；目标代理/函数时间上限应有余量，不能让平台先返回无解释的 504。Vercel 当前默认启用 Fluid Compute 的 Hobby 文档上限为 300 秒，因此不能将“免费版固定 10 秒”当作当前阻塞；需检查实际项目设置。[函数限制](https://vercel.com/docs/functions/limitations)、[时长配置](https://vercel.com/docs/functions/configuring-functions/duration)。

`/api/health` 现在只证明进程存活（且 phase 字段仍是 1），不检查密钥、扶摇连接或数据覆盖。HTTP 200 的筛选响应也可能全部 UNKNOWN。上线验收必须检查实际指标 issue 和证据，不能只看 health/响应状态。

## 可接受的原型限制

- 仅三只已验证 A 股、三个既定指标；固定 2025 年报 ROE、60 日样本波动率口径、AND 和三值判断保持不变。不是全市场覆盖或投资建议。
- 单实例演示中重启/发布、15 分钟到期或容量淘汰后快照失效，已有明确刷新路径；可以作为公开演示的披露限制，但不能承诺故障恢复后继续比较。高流量、无中断或重启恢复要求将触发共享存储必需项。
- 上游异常与数据缺失保持 UNKNOWN，不使用假数据；年报披露日未知、交易日历/停牌和独立复权核验尚未完成，既有 7 个自然日新鲜度规则不能改称供应商 SLA。
- 没有账号或持久化策略，输入只记录想法并由用户手动配置；Qwen 2.5 3B 保持 NO-GO。上线 Phase 2 演示并不等于招聘挑战全部 AI 能力已交付。

## 可选改善

- 推荐单实例方案下，后续使用共享 TTL 存储以保留重启期间的快照；Serverless 方案下此项属于必须实现。
- 增加不含凭证/原始供应商自由文本的错误码、耗时、请求数与 UNKNOWN 覆盖率监控；health 说明版本，设置应用层开销与预算告警。
- 完善安全响应头、数据响应体积上限、构建缓存或 standalone/container 产物。当前不需要为了三个股票重构成微服务，也无需新增 LLM。
